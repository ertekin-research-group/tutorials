Getting Started: DFT for Defects in Semiconductors

Ertekin Group tutorial series. Written for someone who has never compiled a code, never run a DFT calculation, and never used Git. Work through the modules in order.

What this series gets you to. By the end of module 07 you will have built VASP from source on your own laptop, converged your own numerical parameters, relaxed a crystal, computed a band structure, and moved the whole workflow onto an HPC cluster. That is the complete foundation for everything we do afterwards with defects.

Why 04 comes before 05. Notice that convergence testing happens before the first relaxation. This is not tidiness. An unconverged plane-wave cutoff produces Pulay stress, which specifically corrupts cell relaxations — so relaxing a cell with an unconverged ENCUT gives you a lattice constant that is wrong for a reason no amount of careful relaxation will fix. Converge on a fixed structure first, then relax. Learn the reason, not the ritual.

How to work through these

  • In order, without skipping. Each module assumes the previous ones.
  • Type the commands, do not paste them. Slower, and that is the point — you will remember them.
  • When something fails, read the error before doing anything else. Most of learning computational work is getting comfortable with error messages instead of alarmed by them.
  • Ask early. The cost of asking is much smaller than the cost of being stuck for a week. In your first month it is genuinely hard to tell a five-minute problem from a five-day one — that judgment is exactly what you do not have yet, so do not try to exercise it alone.
  • Keep notes as you go. When a module's instructions turn out to be wrong or incomplete on your machine, write down what actually worked. These tutorials get better that way.
A note on Claude. You have Claude Code in VS Code and you should use it — for reading error messages, for explaining what an INCAR tag does, for writing plotting scripts. Two rules. First, never let it write something you could not check: if you cannot tell whether the output is right, you are not ready to delegate that piece. Second, when it fixes something, make sure you understand what was wrong before moving on. The goal is that you become self-sufficient, and a tool that solves problems you never understood works against that.
