03 — The Four Input Files Week 2

What POSCAR, POTCAR, INCAR, and KPOINTS are, where they come from, and how to run VASP in parallel on your laptop.

Goal. Understand every line of a VASP input set well enough to write one from scratch, and know how to launch and monitor a calculation locally. This module is reference material as much as instruction — you will come back to the INCAR tables all semester.

1. The four files

Every VASP run needs exactly these four files in the working directory. No more, no fewer.

FileWhat it isWhere it comes from
POSCAR The crystal structure: lattice vectors and atomic positions. Materials Project, or you build it.
POTCAR Pseudopotentials, one per element, concatenated in POSCAR order. The licensed library from Elif.
INCAR Every calculation parameter: accuracy, what to relax, how to converge. You write it.
KPOINTS How densely to sample reciprocal space. You write it, or generate it with pymatgen.
A useful way to hold these four in your head. POSCAR and POTCAR describe the physical system — what atoms, arranged how. INCAR and KPOINTS describe the numerical approximation — how accurately you are going to solve it. The first pair is physics; the second pair is convergence. Module 04 is entirely about the second pair, and this distinction is why: you converge the numerics until they stop affecting the answer, and then the answer is about the physics.

2. POSCAR — the structure

Getting one from the Materials Project

Either through the website (search the formula, download POSCAR, choose the symmetrized version), or in Python:

from mp_api.client import MPRester
from pymatgen.io.vasp import Poscar
import os

with MPRester(os.environ["MP_API_KEY"]) as m:
    s = m.get_structure_by_material_id("mp-149",
                                       conventional_unit_cell=True)

Poscar(s).write_file("POSCAR")
conventional_unit_cell=True is not optional here. Without it the Materials Project hands back the primitive cell — 2 atoms for silicon, not 8 — and everything downstream silently refers to a different cell than this page describes. Energies are reported per cell, so if you then divide by the wrong atom count your energy per atom is out by a factor of four and nothing warns you.

Anatomy

Si8                          <- line 1: a comment. Free text. Label it usefully.
1.0                          <- line 2: universal scaling factor (usually 1.0)
  5.4437  0.0000  0.0000     <- lines 3-5: the three lattice vectors, in Angstrom
  0.0000  5.4437  0.0000
  0.0000  0.0000  5.4437
Si                           <- line 6: element symbols, in order
8                            <- line 7: how many atoms of each
direct                       <- line 8: 'direct' = fractional, 'cartesian' = Angstrom
  0.75  0.75  0.25           <- lines 9+: positions, grouped by element
  0.00  0.50  0.50
  ...
Line 6 is load-bearing. The element order on line 6 determines the order your POTCAR must be concatenated in. If line 6 says Ga N, then POTCAR must be gallium followed by nitrogen. Get it backwards and VASP runs to completion and gives you a physically meaningless number, with no warning of any kind.
Always put something meaningful on line 1. It costs nothing and it appears in the OUTCAR. When you are staring at forty directories in Week 10 wondering which is which, GaN 96-atom V_N q=+1 is worth a great deal more than Si8.

Conventional vs primitive cells

Silicon can be described as an 8-atom cubic cell (conventional, easy to picture) or a 2-atom rhombohedral cell (primitive, four times cheaper). Both describe the same crystal. Use the primitive cell when you want speed, the conventional cell when you want a shape that is easy to reason about, and be aware which one you have — energies are reported per cell, so always compare energies per atom.

from pymatgen.core import Structure
from pymatgen.symmetry.analyzer import SpacegroupAnalyzer

conv = Structure.from_file("POSCAR")
prim = SpacegroupAnalyzer(conv).get_primitive_standard_structure()
print(len(conv), "->", len(prim), "atoms")

3. POTCAR — the pseudopotentials

A POTCAR is the per-element pseudopotential files concatenated together, in POSCAR order:

# one element
cp ~/vasp_pseudo/Si/POTCAR POTCAR

# two elements -- ORDER MUST MATCH POSCAR LINE 6
rm -f POTCAR      # see below
cat ~/vasp_pseudo/Ga/POTCAR ~/vasp_pseudo/N/POTCAR > POTCAR
Why the rm -f first. POTCARs in the library are read-only, and cp preserves that. So if a POTCAR is already sitting in the directory, cat ... > POTCAR fails with permission denied — the shell cannot open the existing read-only file for writing. Removing it first sidesteps the whole issue.

Choosing a variant

The library has several potentials per element. The suffix tells you what is treated as a valence electron:

VariantMeaningWhen to use it
SiStandard PAW.The default. Most work.
Ga_dSemicore d electrons treated as valence. Often necessary for Ga, In, and similar. We will investigate this explicitly for GaN in Week 6.
_pv, _svSemicore p or s as valence. High pressure, magnetism, or when the standard one is known to fail.
_GWHarder potential, needs much higher ENCUT. GW and some hybrid calculations only. Expensive.
Why this choice is not cosmetic. A pseudopotential replaces the core electrons with an effective potential, on the assumption that they do not participate in bonding. When that assumption is marginal — as it is for gallium's 3d states — the choice measurably changes lattice constants and band gaps. This is a physics decision disguised as a filename, which is exactly why we will test it rather than assume it in Week 6.

Verify what you built

head -1 POTCAR                      # e.g. "PAW_PBE Si 05Jan2001"
grep -c "End of Dataset" POTCAR     # number of elements -- check it matches POSCAR
grep ENMAX POTCAR                   # recommended minimum cutoff, per element

ENMAX is the potential's own recommendation for the minimum plane-wave cutoff. It is a floor, not a converged value — establishing the actual converged value is module 04's job.

4. INCAR — the parameters

A plain text file of TAG = value pairs. Order and spacing do not matter; # starts a comment. Every tag has a default, so you only set what you want to override.

A commented skeleton

# Si bulk, static calculation
SYSTEM = Si static      # label, appears in OUTCAR

# --- accuracy ---
PREC   = Accurate       # grid density preset
ENCUT  = 520            # plane-wave cutoff, eV  <-- module 04 justifies this
LREAL  = .FALSE.        # real-space projection off (accurate; fine for small cells)
LASPH  = .TRUE.         # aspherical corrections; recommended for all GGA

# --- electronic convergence ---
EDIFF  = 1E-6           # stop SCF when energy changes less than this (eV)
NELM   = 80             # max electronic steps
ALGO   = Normal         # SCF algorithm
ISPIN  = 1              # 1 = non-magnetic, 2 = spin-polarized

# --- Brillouin-zone integration ---
ISMEAR = 0              # Gaussian smearing (correct for semiconductors)
SIGMA  = 0.05           # smearing width, eV

# --- ionic motion ---
NSW    = 0              # 0 = static, no ionic steps
IBRION = -1             # no ion mover

# --- parallelization (see section 6) ---
KPAR   = 2
NCORE  = 4

# --- what to write ---
LWAVE  = .FALSE.        # do not save WAVECAR (large)
LCHARG = .FALSE.        # do not save CHGCAR (large)

The tags you will actually adjust

How to start a new INCAR: copy the closest one you already have and change only what differs. Do not write one from a blank file — you will omit a tag and not notice. This is also why keeping your working INCARs in Git matters.

5. KPOINTS — Brillouin zone sampling

A uniform mesh (almost always what you want)

Automatic mesh          <- comment
0                       <- 0 means "read the grid below"
Gamma                   <- Gamma-centered (vs 'Monkhorst')
9 9 9                   <- subdivisions along each reciprocal lattice vector
0 0 0                   <- shift; leave at zero
What you are actually choosing. Physical properties require integrals over the Brillouin zone, and VASP approximates those integrals by a finite sum over a grid of k-points. More k-points means a better approximation and more cost. The right density depends on the cell: a large cell has a small Brillouin zone and needs fewer k-points. This is why a 96-atom defect supercell can often be run with a 2×2×2 mesh while a 2-atom primitive cell needs 12×12×12 — and why you must re-converge whenever the cell size changes.
Use Gamma, not Monkhorst, for hexagonal cells like GaN and AlN. A shifted mesh breaks the hexagonal symmetry and can give subtly wrong answers. Gamma-centered is always safe.

Line mode, for band structures

Do not write these by hand. Generate them with pymatgen — module 06 has a working script.

6. Running VASP on your laptop

conda activate defects
cd ~/research/myrepo/si_test
mpirun -np 8 $VASP_STD | tee run.log
You must activate the conda environment before running. VASP is linked against the MPI and math libraries inside that environment. Without it activated, you will get a cryptic "library not found" error.

How many cores?

Apple Silicon splits its CPU into tiers, and the naming has changed across generations, so ask the machine rather than assuming:

sysctl -n hw.ncpu                      # total cores
sysctl -n hw.perflevel0.physicalcpu    # cores in the fastest tier
sysctl -n hw.perflevel1.physicalcpu    # cores in the second tier (may not exist)

perflevel0 is always the fastest tier. On older M-series chips the second tier is genuinely slow "efficiency" cores you should avoid. On newer ones the second tier is much closer in speed to the first, and may be worth using. The safe default either way:

  • Start with -np equal to your perflevel0 count, minus one or two so the laptop stays usable.
  • If a second tier exists, time a short run both ways before trusting it. Adding ranks is only a win if the extra cores keep up.
Benchmark, do not guess. Take one of your convergence runs from module 04, run it at a few different -np values, and record the wall times. Ten minutes of measurement beats a rule of thumb that was written for a different chip — and you will want the timings for your methods section anyway.
More ranks is not always faster. MPI splits work evenly across ranks, so every rank waits for the slowest one. Putting ranks on slower cores drags the whole calculation down to their speed — which is why a mixed-tier run can be slower than using the fast tier alone.

KPAR and NCORE

TagWhat it splitsLaptop guidance
KPARDivides MPI ranks into groups, each handling different k-points. Very effective when you have many k-points. Must divide -np evenly. Try 2 or 4.
NCORENumber of ranks working together on one orbital. 2 or 4. Larger helps for big cells, hurts for small ones.

Constraint: KPAR must divide the total rank count, and NCORE must divide what is left in each group. Work it out as ranks per group = -np ÷ KPAR, then pick an NCORE that divides that:

-npKPARRanks per groupValid NCORE
4221, 2
6231, 3
8241, 2, 4
8421, 2
12261, 2, 3, 6
16441, 2, 4

So on 6 cores with KPAR = 2, NCORE = 3 is the right answer — 2 does not divide 3. Get this wrong and VASP will either complain or quietly reduce NCORE for you.

Do not spend time optimizing this now. KPAR=2, NCORE=2 with -np 8 is fine for everything in modules 04–06. Parallel tuning matters in Week 12 on the cluster, where the calculations are large enough to justify the effort.

7. Reading the output

FileWhat it holdsSize
OSZICARConvergence history, one line per SCF step. Your first stop.Tiny
OUTCAREverything. Energies, forces, timing, warnings.Large
CONTCARThe final structure. Same format as POSCAR.Tiny
vasprun.xmlMachine-readable everything. What pymatgen parses.Large
WAVECARThe wavefunctions. Binary.Very large
CHGCARThe charge density. Needed for band structures.Large

The commands you will use constantly

# Did it converge? Watch it live:
tail -f OSZICAR

# Final total energy:
grep "free  energy   TOTEN" OUTCAR | tail -1

# Did the ionic relaxation actually converge?
grep "reached required accuracy" OUTCAR

# Any warnings?
grep -i "warning" OUTCAR

# Forces on each atom (last ionic step):
grep -A 10 "TOTAL-FORCE" OUTCAR | tail -12
"It finished" is not "it converged." VASP will exit normally after hitting NELM electronic steps without converging, and after hitting NSW ionic steps with atoms still moving. Nothing in the output shouts about it. Check convergence explicitly, every single time. In module 04 you will automate this check, which is the only way it happens reliably.

Reading OSZICAR

       N       E                     dE             d eps       ncg     rms          rms(c)
DAV:   1    -0.437150583428E+02   -0.43715E+02   -0.11577E+04  3360   0.352E+02
DAV:   2    -0.435891255013E+02    0.12593E+00   -0.19334E+00  4368   0.242E+01
...
   1 F= -.43589126E+02 E0= -.43589126E+02  d E =-.435891E+02

The DAV: lines are electronic steps; watch the third column (dE) shrink toward your EDIFF. The F= line marks the end of one ionic step.

8. What to commit

Copy gitignore_template in this directory to .gitignore at the root of your repository:

cp ~/path/to/tutorials/03_vasp_inputs/gitignore_template ~/research/myrepo/.gitignore
cd ~/research/myrepo && git add .gitignore && git commit -m "Ignore VASP binary output"

Commit inputs and small text results. Never commit WAVECAR, CHGCAR, or vasprun.xml.

Never commit a POTCAR. They are licensed and cannot be redistributed — including to a private repository, which may not stay private forever. The .gitignore covers this, but know the rule rather than relying on the file.

9. Common mistakes

MistakeWhat happensHow to catch it
POTCAR order does not match POSCAR Runs fine. Answer is meaningless. head -1 POTCAR and count End of Dataset. Build a reflex.
ENCUT too low Energies wrong; cell relaxations wrong via Pulay stress. Module 04. Never skip it.
ISMEAR = -5 with too few k-points VASP errors out or gives nonsense. Use ISMEAR = 0 unless you specifically want tetrahedron DOS.
Two calculations in one directory Files silently overwrite each other. One directory per calculation. No exceptions.
Forgot conda activate Library not found, or wrong Python. which python, which mpirun.
Comparing energies from different cell sizes Nonsensical comparison. Always divide by the number of atoms.
Assuming "finished" means "converged" You publish an unconverged number. grep "reached required accuracy" OUTCAR.

10. Exercises

  1. Download the silicon structure from the Materials Project two ways — website and Python. Confirm the files agree.
  2. Convert the 8-atom conventional cell to the primitive cell. How many atoms? Why is that a sensible number?
  3. Build a POTCAR for silicon. Find its ENMAX. What is 1.3 × that?
  4. Write an INCAR for a static silicon calculation from scratch, without copying the skeleton above. Then compare against it and note what you omitted.
  5. Run the calculation with -np 4. Find the total energy. Divide by the number of atoms.
  6. Run the same calculation with -np 8. Confirm the energy is identical (to within a fraction of a meV) and note the wall-time difference. Parallelization must not change the answer — if it does, something is wrong with the build.
  7. Deliberately break something: swap POTCAR order in a two-element system, or drop ENCUT to 200. Look at what the output does — and does not — tell you. This is the most valuable exercise on the page.
