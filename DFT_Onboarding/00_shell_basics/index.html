00 — Shell Basics Week 1

The command-line vocabulary that every other module assumes. Written for macOS (zsh). Everything here works on your laptop — nothing in this module needs a cluster.

Goal. Be able to move around the filesystem, inspect files, search inside them, edit them, and understand what PATH is, without reaching for the Finder. You do not need to be fast. You need to stop being lost.

1. Opening a terminal

Press Cmd+Space, type Terminal, hit return. You will get a window with a prompt that ends in %. That is zsh, the default macOS shell.

You will mostly use the terminal built into VS Code instead (Ctrl+`), which is the same thing in a more convenient place. Either is fine.

ShortcutWhat it does
Ctrl+CKill whatever is currently running. Your escape hatch.
Ctrl+A / Ctrl+EJump to start / end of the line.
Cmd+KClear the screen (Terminal.app).
TabAutocomplete. Use this constantly — it prevents typos in long paths.
↑ / ↓Scroll back through commands you already ran.
Tab-completion is not optional. Type the first few letters of a directory name and press Tab. If you are typing full paths by hand you are working much harder than necessary and introducing typos that produce confusing errors later.

2. Where am I? Navigation

pwd                     # print working directory -- "where am I?"
ls                      # list files here
cd ~/Desktop            # change directory (~ means your home folder)
cd ..                   # go up one level
cd -                    # jump back to where you just were
cd                      # with no argument: go home
CommandWhat it does
lsList visible files.
ls -lLong form: permissions, size, date.
ls -laInclude hidden files (those starting with .).
ls -lhHuman-readable sizes (1.2K, 3.4M).
ls -ltSort by time, newest first. Very useful for "what did my run just write?"

Paths

An absolute path starts from the root: /Users/you/research/si. A relative path starts from wherever you are: si/relax, or ../bulk. Both are fine; absolute paths are safer in scripts, relative paths are faster to type.

Never put spaces in directory names for calculations. macOS lets you do it, and the Finder encourages it, but my si run/ will break scripts in ways that are annoying to debug. Use my_si_run/ or si-run/. Same for &, (, ), and #.
You can drag a folder from the Finder into a terminal window and it will paste the full path. Handy when you are not sure where something lives.

3. Looking at files

cat INCAR               # dump the whole file (small files only)
less OUTCAR             # page through a big file: q to quit, / to search
head INCAR              # first 10 lines
head -n 30 INCAR        # first 30 lines
tail OSZICAR            # last 10 lines
tail -f OSZICAR         # FOLLOW a file as it grows -- watch a run live
wc -l OUTCAR            # count lines
du -sh *                # how big is everything here?
tail -f OSZICAR is how you watch a VASP calculation converge in real time. Ctrl+C to stop watching (this does not stop the calculation).
Never cat an OUTCAR or a WAVECAR. OUTCARs are tens of thousands of lines and WAVECARs are binary — you will flood your terminal with garbage. Use less, head, tail, or grep.

4. Creating, copying, moving, deleting

mkdir si_relax          # create a directory
mkdir -p a/b/c          # create nested directories in one go
touch notes.txt         # create an empty file
cp INCAR INCAR.bak      # copy a file
cp -r run1/ run2/       # copy a directory and everything in it
mv old.txt new.txt      # rename
mv notes.txt ../        # move
rm notes.txt            # delete a file
rm -r oldrun/           # delete a directory and its contents
rmdir empty_dir/        # delete a directory only if it is empty (safer)
rm is permanent. There is no Trash and no undo. Be especially careful with wildcards: rm -rf * in the wrong directory will ruin your afternoon. Two habits that prevent this: run pwd before any rm -r, and run ls on a wildcard before you rm it — if ls *.out lists what you expect, then rm *.out is safe.
Copy the closest thing you already have. When you need a new calculation, cp -r a working directory and edit what differs. Do not build inputs from scratch each time — you will forget a tag.

5. Searching for files and text

Finding files

find . -name "POSCAR"           # by exact name, recursively from here
find . -name "*.py"             # by pattern
find . -type d -name "relax*"   # directories only
find . -name OUTCAR -mtime -1   # modified in the last day

Searching inside files

grep "TOTEN" OUTCAR             # lines containing TOTEN
grep -i "error" *.out           # case-insensitive, across several files
grep -n "ENCUT" INCAR           # show line numbers
grep -r "ISMEAR" .              # recursively through everything below here
grep -c "TOTEN" OUTCAR          # just count the matches

These two combine into the single most useful command you will learn this week:

grep "free  energy   TOTEN" OUTCAR | tail -1

That pulls the final total energy out of a VASP run. Note the double spaces — VASP's output formatting is fixed-width, so the spacing matters. You will use this constantly, and in module 04 you will automate it.

Combine grep across many runs at once: 
grep "free  energy   TOTEN" */OUTCAR | tail -20
This is how you compare a whole sweep of calculations in one line — exactly what you will want in module 04.

6. Editing files in the terminal

Most of the time you will edit files in VS Code, which is easier. But you need some terminal editor for when you are working over SSH (module 07).

nano — easy, start here

nano INCAR

Type normally. The bottom bar shows the shortcuts, where ^ means Ctrl: ^O to save, ^X to exit.

vim — the minimum to survive

You will eventually open a file in vim by accident, or land on a machine without nano. Learn just enough to get out:

KeysEffect
iStart typing (insert mode).
EscStop typing (back to normal mode).
:wSave.
:wqSave and quit.
:q!Quit, throwing away changes. The escape hatch.
/textSearch forward; n for next match.
uUndo.

7. Redirection and pipes

command > out.txt        # send output to a file (OVERWRITES it)
command >> out.txt       # append instead
command 2> err.txt       # send error messages to a file
command > all.txt 2>&1   # send both output and errors to one file
command1 | command2      # pipe: feed command1's output into command2

Pipes are what make the shell powerful. Each command is small; you chain them:

grep "TOTEN" OUTCAR | tail -1 | awk '{print $5}'

Find the energy lines, take the last one, print the fifth field. You do not need to master awk — just recognize that this is how small tools combine into a specific answer.

8. Environment variables and PATH

echo $HOME              # print one variable
echo $PATH              # the list of directories searched for commands
which python            # WHICH python am I actually running?
export MYVAR=hello      # set a variable for this shell session only
env | grep -i conda     # list variables mentioning conda
Why PATH matters to you. When you type python, the shell searches the directories in PATH, in order, and runs the first match. This is why which python is the first thing to check when a package "isn't installed" — usually it is installed, but in a different Python than the one you are running. You will hit this. Expect it.

Making a setting permanent

Variables set with export vanish when you close the terminal. To make one persist, put it in ~/.zshrc, which zsh reads every time it starts:

nano ~/.zshrc                    # add your line, save, exit
source ~/.zshrc                  # re-read it in the current shell
Keep ~/.zshrc tidy and understand every line in it. A mysterious export you added six months ago and forgot is a genuinely nasty source of "it works on my machine" problems. When you add something, add a comment saying why.

9. Permissions and executables

ls -l shows something like:

-rwxr-xr-x  1 alex  staff  55861656 Aug 27 21:40 vasp_std
 ^^^ ^^^ ^^^
 ||| ||| `--- everyone else (r=read, w=write, x=execute)
 ||| `------- your group
 `----------- you (the owner)
CommandEffect
chmod +x script.shMake a file executable. Needed for scripts and binaries.
chmod 644 fileOwner read/write; everyone else read-only.
chmod 700 dirOnly you can read, write, or enter it.
If you get permission denied trying to run something you just wrote, you almost certainly need chmod +x on it. Your vasp_std binary will need this too.

10. Habits worth building now

  • pwd before anything destructive. Cheap insurance.
  • One directory per calculation. Never run two calculations in the same folder — VASP writes fixed filenames and they will overwrite each other silently.
  • Name directories so they sort correctly. encut_300, encut_350, encut_400 — and use encut_0300 style zero-padding if you will go into four digits, so ls orders them sensibly.
  • Keep a README or notes.md in every project directory. Write what you were trying to do. In three weeks you will not remember, and a directory called test3_new_v2 tells you nothing.
  • Never edit files only on a remote machine. Everything important lives in Git (module 01).

11. Exercises

Do these before the Week 1 meeting. They take about thirty minutes and they are the difference between having read this and being able to use it.

  1. Make a directory ~/research/practice and cd into it. Confirm with pwd.
  2. Create three files named run_01.txt through run_03.txt with touch. List them sorted by time.
  3. Put the text ENCUT = 400 into run_01.txt using redirection (not an editor).
  4. Use grep to find which of the three files contains the word ENCUT.
  5. Copy run_01.txt to run_04.txt, then edit run_04.txt in nano to say ENCUT = 500.
  6. Run grep -r "ENCUT" . from the parent directory and make sure you understand every line of the output.
  7. Run which python and echo $PATH. Be ready to explain in the meeting what the relationship between those two outputs is.
  8. Delete the practice directory entirely — carefully, and after running pwd.
